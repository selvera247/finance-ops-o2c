# Internal ops mirror — AI-native delivery credibility (OCFO)

**Purpose:** Eliza’s own delivery process should use the same discipline it sells: structured discovery, measurement contracts, standardized handoffs, human gates, pattern reuse.  
**Audience:** Deployment Managers, FDEs, Enablement, practice lead.

**Assumption:** Small, fast-growing team—lightweight rituals beat heavy PMO.

---

## 1. Thesis (internal)

| External promise | Internal mirror |
| --- | --- |
| Structured discovery | Every OCFO engagement uses [discovery format](./ocfo-discovery-output-format.md) |
| Measurement contract | [Value-capture checkpoint](./ocfo-value-capture-checkpoint.md) at baseline + post |
| Clean handoffs | [Handoff package](./ocfo-handoff-package-template.md) before build starts |
| Human judgment on material decisions | Internal scope/gates reviewed by DM + practice lead |
| Faster 2nd/3rd engagement | Process kits (e.g. [cash-app](./ocfo-kit-cash-app-exceptions.md)) + pattern tags |

---

## 2. Delivery spine (every engagement)

```
Discover (fill template) → Gate → Handoff freeze → Build/Enable
    → Pilot → Value checkpoint → Pattern extract → Kit update
```

**Roles**
- **DM:** discovery quality, golden-set labeling plan, user sessions, eval readout, gates, value narrative  
- **FDE:** ingest, integration, permissions, audit, custom UX  
- **Enablement:** workspace/GPT/policy packs when path B  
- **Practice lead:** pattern promotion, staffing, stop/revise support  

---

## 3. AI inside our delivery (not only client systems)

| Work | AI-native habit | Human gate |
| --- | --- | --- |
| Discovery notes → structured pack | Draft sections from transcripts/artifacts | DM verifies against shadowing |
| Requirements → ACs | Propose Given/When/Then | DM + FDE accept |
| Eval triage | Cluster failure modes | DM prioritizes fixes |
| Kit updates | Diff “client-specific vs reusable” | Practice lead merges kit |
| Status / risk | Summarize blockers weekly | DM owns client wording |

**Forbidden internally:** inventing client baselines; skipping ACL/security language; claiming value without Checkpoint 0.

---

## 4. Cadence (lightweight)

| Ritual | When | Artifact |
| --- | --- | --- |
| Discovery stand-up | 2–3×/week in W1–2 | Open questions in discovery §8 |
| Go/revise gate | End discovery | Discovery §9 + handoff start |
| Thin-slice review | ~W4 | Working path + AC status |
| Pilot office hours | Weekly | Session notes → failure modes |
| Value checkpoint | Mid + end pilot | Value-capture doc |
| Pattern harvest | Within 5 days of close | Kit PR / doc update |

---

## 5. Definition of “practice-ready” engagement close

- [ ] Discovery frozen version filed  
- [ ] Handoff signed (or Enablement equivalent)  
- [ ] Checkpoint 0 + final checkpoint filed  
- [ ] Scale/revise/stop recorded with sponsor  
- [ ] Kit/pattern tags updated (or “no new pattern” noted)  
- [ ] 5-bullet internal retro: what to reuse next time  

---

## 6. Credibility checks (ask ourselves)

1. Would we accept this discovery pack from a client team as build-ready?  
2. Can a second DM run the same measurement defs without us?  
3. Did we keep human gates on material finance actions?  
4. Is the second similar engagement actually cheaper/faster—and did we write down why?
